# Portfolio design rules

Read `design.md` before changing presentation, content organization, or motion. It is the source of truth; apply an explicit new user decision there and in code together.

- Keep the focused four-section structure: introduction, one selected-project workspace, experience, contact. Use manual project/evidence selection; do not reintroduce vertical project stacks or decorative supporting scenes.
- Use the light canvas with floating navy header/footer and dark technical scenes, following shared type/spacing tokens in `dist/design-system.css`; canvas reads them via `dist/theme.js`. No gradients, blur, glow, ornamental rules, or arbitrary font systems.
- System Anatomy is the signature interaction. Preserve its source-grounded, permanently exploded process stories, machinery and documented relationships, original hero elements, and the existing ML workflow. Activity must explain a specific stage; no arbitrary traffic on every cable. Keep the in-flow narration and static transcript.
- All scene motion uses elapsed time and repeats independently of scrolling. Entry cues never scrub/restart/seek the base loop. Preserve system reduced motion and hidden/offscreen suspension. Inspection and camera gestures must not pause or reset the process clock. No playback controls.
- No content cards, corner captions, decorative numbering, skill pills, hidden-text scroll reveals, pinned stories, or forced scroll snapping. Functional controls and modal readers may have bounded surfaces.
- Preserve original images, captions, provenance, same-page evidence inspection, and documented claim limits. Keep ML claims unchanged and detailed n8n workflows deferred until supplied.
- Preserve keyboard navigation, visible focus, native vertical scrolling/pinch, image aspect ratios, and pointer fallbacks. Never hide information solely because motion is disabled.
- Keep the existing Sites identity, audience, and static architecture. No new framework solely for presentation.
